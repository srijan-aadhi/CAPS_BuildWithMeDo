CAPS (Context-Aware Prompt Snippets) — project brief + status
Use this file to refresh context when memory resets or onboarding new chats.

================================================================================
PIVOT SUMMARY (2026-05-14)
================================================================================

Original direction (deprioritized)
- Boost: LLM-enhanced prompt rewriting before sending to inline chat.
- Reason deprecated as primary feature: redundant with existing AI tools (Copilot,
  Cursor, Claude) that already iterate on prompts inline. Developers don't want a
  pre-flight step; they just type and iterate.

New direction
The extension's defensible value is team-specific prompt delivery. Generic AI tools
don't know your codebase conventions, your service patterns, your team rules. The CAPS
library does — because your team wrote those prompts. The extension is the last-mile
delivery mechanism that puts them at the cursor without leaving the IDE.

The pivot in one sentence:
CAPS is a team prompt library that lives in the IDE — not a prompt enhancer.

DONE (VS Code extension, current codebase)
- Trigger: user types //? ; completion fires on ?.
- Snippet list: fetched directly from Supabase REST API (/rest/v1/prompts); dropdown
  shows title, category, markdown docs. Ordered by vote_count descending.
- Schema: reads id, title, prompt_text, category, tags, vote_count from `prompts` table.
  Handles both plain array and { prompts: [] } envelope responses.
- Inline chat handoff: selecting a snippet opens inline chat with the snippet's prompt
  text prefilled (tries multiple VS Code command/argument shapes; falls back to
  clipboard + sidebar chat if prefill fails).
- No prompt pasted into the source file on accept: insertText is empty; only inline
  chat receives the prompt.
- Credentials / URLs: not hardcoded in shipping paths (except public anon key, which
  is safe to ship). Resolution order:
  - API mode override: CAPS_SNIPPETS_API_URL + optional CAPS_SNIPPETS_API_BEARER.
  - Direct Supabase REST override: CAPS_SNIPPETS_URL + CAPS_API_KEY when both set.
  - Default: direct Supabase REST at zrcciaqiewveljumkcvz.supabase.co using built-in
    public anon key (role: anon, expires 2036). Zero setup required.
  - Anon key override: CAPS_SUPABASE_ANON_KEY env var or "CAPS: Set Supabase anon key".
- Operator commands: set/clear snippets API URL, bearer, direct URL, direct key,
  Supabase anon key, Anthropic key; clear all CAPS secrets.
- Logging: CAPS output channel; clearer errors on bad HTTP/HTML responses.
- Boost (secondary feature, kept but deprioritized):
  - @caps chat participant: type "@caps <rough prompt>" in inline/panel chat to enhance.
  - caps.boostPrompt command: right-click selected text or Command Palette; shows
    enhanced prompt in editable input box before firing to inline chat.
  - CodeLens: "Boost with CAPS" lens appears above selected text in editor.
  - Credential: CAPS_ANTHROPIC_API_KEY env var or "CAPS: Set Anthropic API key".
- Context injection: prompts use {{selection}}, {{filename}}, {{filepath}}, {{language}}
  placeholders. Extension snapshots editor context before any async UI opens, then
  substitutes before handoff to inline chat. Works in both //? completion and
  caps.pickPrompt command paths.
- Fuzzy search / filter:
  - caps.pickPrompt QuickPick: matchOnDescription + matchOnDetail enabled; prompts
    grouped by category with separators; tags shown in description row; searching
    matches title, category, tags, and prompt body preview.
  - //? completion: filterText per item encodes title + category + tags so typing
    after the trigger filters the list beyond just the title.
- Keyboard-first navigation: satisfied natively — QuickPick supports arrow keys +
  Enter; //? completion widget supports full keyboard navigation out of the box.
- Recently used / favorites: last 5 picks stored in globalState; surfaced as a
  "Recently Used" separator section at the top of caps.pickPrompt QuickPick; sorted
  to the top of the //? completion list via sortText. Both trigger paths (QuickPick
  and //? completion) update the list on accept via caps.completionAccepted.
- Simplified trigger: @@ typed anywhere in an editor opens caps.pickPrompt QuickPick
  immediately (onDidChangeTextDocument listener detects @@, deletes the two chars,
  fires the command). //? completion trigger kept alongside for backwards compat.
- Prompt caching: 60-second in-memory cache (SnippetCacheEntry in activate closure)
  shared by both the QuickPick and //? completion paths. Cache keyed by fetch config
  fingerprint — auto-invalidates if API URL or credentials change. QuickPick title
  shows "(cached Xs ago)" or "(refreshed)" so cache state is visible. CAPS output
  channel auto-shown on activation (output.show(false)); all fetch/cache events logged.

ARCHITECTURE DECISION (2026-05-12)
- MeDo web app is deployed but HTTP routing to it from the extension is broken
  (unknown platform issue). Extension bypasses MeDo entirely.
- Data layer: extension queries Supabase REST directly (no edge function, no MeDo API).
- MeDo web app continues to serve the frontend UI (prompt CRUD, voting, collections).
  Extension is read-only against the same Supabase backend.

NOT STARTED (roadmap — prioritized)
1. TEAM PROMPT MAINTENANCE (MeDo side)
   Versioning, "mark as official", deprecation notices shown inline in the dropdown.
   Why: if the library has stale prompts it loses trust. Teams need a way to flag
   the canonical, maintained prompts vs. personal experiments.

KNOWN TECHNICAL CAVEATS
- VS Code / Copilot inline chat command IDs and argument objects vary by version;
  extension uses a small compatibility matrix + fallback.
- Cursor may behave differently from VS Code; validate inline chat on each host.
- MeDo HTTP routing issue: requests sent directly to the MeDo app URL fail for an
  unknown reason. Workaround is direct Supabase REST (in place). Root cause unresolved.
- Supabase anon key is hardcoded as a default constant (public key, safe to ship);
  override via secret storage or env var if the key rotates.
- VS Code inline chat input text cannot be set programmatically from an extension.
  inlineChat.start with initialInput/message args is silently ignored when VS Code
  detects a code action at the cursor (shows "Fix the problem" instead). The fire-
  and-forget + selectAll + type approach was attempted but did not work reliably.
  Current workaround: selection is cleared and cursor nudged off diagnostics before
  opening inline chat; prompt is copied to clipboard; user presses Ctrl+A, Ctrl+V.

VISION SUMMARY (revised)
================================================================================

Problem
Developers lose flow hunting for the right prompt — browsing notes, Notion docs, or
re-typing the same instructions from memory every time. Worse, every developer on a
team describes the same codebase context differently, so AI output quality varies
person to person. CAPS solves both.

Core goal
Give teams one place to write and maintain high-quality, context-aware prompts, and
deliver them in the IDE at the exact moment they're needed — with the right code
context already attached.

Who it's for
Teams with established conventions that AI tools don't inherently know:
- Specific service/module patterns ("always extend BaseService")
- House rules ("no new npm packages without approval")
- Recurring task templates ("write a test following our fixture convention")
Solo developers with a personal library of battle-tested prompts they reach for often.

What the extension does
At the cursor, surfacing the right team prompt faster than typing from scratch —
with the selected code already injected so the AI gets full context immediately.

What the extension does NOT do
Replace GitHub Copilot, Cursor, or Claude. It feeds them better inputs.

Web hub ("MeDo")
Where the library lives. Teams author, version, vote on, and deprecate prompts.
The extension is the read-only consumer. The quality of the extension experience is
directly proportional to the quality of the library.

One-line elevator pitch
CAPS puts your team's best AI prompts at the cursor, pre-loaded with your code context,
so every developer gets the same quality output — without leaving the IDE.
